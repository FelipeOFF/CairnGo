# Phase 8 Plan 01 — make the lineage visible and give existing installs a way out

## Why

Phase 7 fixed the source and made the install honest at `/cairn:init` time. But
init runs once. A repo can drift — a reinstall, a different machine, a policy that
blocks third-party bundles — and the fusion goes quiet again with nothing to
notice it. Doctor is the recurring check, so that is where the state belongs.

Separately, plugin dependencies resolve by name, and the name changed. Everyone
currently installed keeps a GSD that cannot host the capability until they act,
and they need to be told how without being told to start over.

## Tasks

1. **`check_gsd_capability`** in `cairn-doctor.py`, delegating to
   `cairn-capability.py detect --json` so the lineage rules live in one place.
   FAIL for a legacy lineage or an unregistered capability; WARN when no GSD
   binary is discoverable; OK when registered and completely staged.

2. **`CAIRN_GSD_BIN`** in `cairn-capability.py` — an explicit override for the
   discovery step, because this is the one check reading global rather than repo
   state and it must be pinnable.

3. **Deprecated marketplace entry.** Re-add `gsd` sourcing the 4.x line, with a
   description that states the consequence and the removal version.

4. **Migration guide** (`cairn/docs/gsd-core-migration.md`): why it matters, how to
   check, the four commands to migrate, the window, what changed underneath, and
   troubleshooting for the three failure shapes actually seen.

5. **Docs + CHANGELOG.** Doctor's check list and sample output; README's plugin
   table; an Unreleased CHANGELOG section covering the migration.

6. **Tests.** The healthy doctor fixture gains a pinned capability stub so every
   existing doctor test stays hermetic, plus four new tests: legacy fails,
   unregistered fails, a bundle missing its gate script fails, no binary warns.

## Verification

- `cairn-doctor` on this repo reports `✗ gsd-capability` with the upgrade command —
