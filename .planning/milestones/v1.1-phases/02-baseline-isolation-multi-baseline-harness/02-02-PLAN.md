  <behavior>
    - Given a manifest whose one git-type plugin_dirs entry points at a local fixture git repo tagged "v0.0.1" with a trivial package.json (no real dependencies) and build=["npm install"], staging clones it into staged_path and, after success, writes staged_path/.staged-ref containing exactly "v0.0.1".
    - Given the same manifest run a second time (staged_path already exists with a matching .staged-ref), staging exits 0 without re-invoking git clone — provable by removing the fixture source repo after the first run and confirming the second run still succeeds.
    - Given a manifest whose build command is intentionally broken (always exits non-zero), staging exits non-zero (EXIT_USAGE) and staged_path/.staged-ref is never written.
    - Given a manifest with a local_path entry pointing at a directory that does not exist, staging exits non-zero (EXIT_USAGE) before attempting any git operation.
  </behavior>
  <action>
    Create benchmarks/scripts/stage-plugins.py, following bench-run.py's exact house style: a module docstring block, EXIT_OK=0/EXIT_USAGE=2 constants, a local die(msg, code) helper, hand-rolled `while i < len(argv)` argv parsing matching bench-run.py's own idiom (not cairn-relabel.py's argparse — this script shares bench-run.py's simple two/three-flag contract shape). CLI: `--baseline <manifest.json>` (repeatable — accept the flag multiple times to stage several manifests in one invocation; collect into a list) or `--all` (glob every benchmarks/baselines/*.json).

    For every collected manifest, load and validate it with the identical parse-then-required-keys shape as `load_baseline()` in bench-run.py (deliberately duplicated here — this script and bench-run.py are separate entry points per RESEARCH's Architectural Responsibility Map: "Runner, pre-flight staging step" vs. the runner's own per-invocation validation).

    For every entry in provisioning["plugin_dirs"]:
    - If source["type"] == "local_path": verify `Path(entry["staged_path"]).is_dir()`, die loud (naming the plugin) if not — no fetch.
    - If source["type"] == "git": compute `staged = Path(entry["staged_path"])`. If `staged.is_dir()` and `(staged / ".staged-ref").is_file()` and its stripped text equals `source["ref"]`, print `"[stage-plugins] {plugin} already staged at {ref}, skipping"` and continue (idempotent skip — no re-clone, no re-build). Otherwise: remove `staged` if present (`shutil.rmtree(ignore_errors=True)`), clone into a sibling temp dir first (`tempfile.mkdtemp()` then `subprocess.run(["git", "clone", "--branch", ref, "--depth", "1", f"https://github.com/{repo}.git", tmp_dir], check=True)`), then for each command string in `entry.get("build", [])` run `subprocess.run(shlex.split(cmd), cwd=tmp_dir, check=True)` (shlex from stdlib — never shell=True). If the staged plugin's own `.claude-plugin/plugin.json` exists and declares an `mcpServers` entry whose `command` is `"node"`, run `subprocess.run(["node", "--check", <resolved args[0] with ${CLAUDE_PLUGIN_ROOT} substituted for tmp_dir>], check=True)` as a syntax-only post-build sanity check (never starts the MCP server, never blocks on stdio) — die loud if this fails. Only once every step succeeds: `(tmp_dir / ".staged-ref").write_text(ref)`, then `shutil.move(str(tmp_dir), str(staged))` (atomic rename-on-success — a failed/partial attempt never leaves something at the real staged_path that looks complete).

    Wrap every `subprocess.run(..., check=True)` call in a `try/except subprocess.CalledProcessError` that calls `die(f"staging '{plugin}' failed at step '...': {e}", EXIT_USAGE)` so failures are always loud and attributed to the specific plugin/step. Print one summary line per manifest staged (`"[stage-plugins] {baseline_name}: N plugin(s) staged/verified"`), mirroring cairn-relabel.py's final-count convention. Its own process exit code is EXIT_OK (0) only if every plugin_dirs entry across every requested manifest staged/verified successfully; EXIT_USAGE (2) on the first failure.

    Add `benchmarks/plugins/` to the repo's root .gitignore (a new line, grouped near the existing entries) — staged checkouts are disposable and reproducible from the pinned ref in the manifest; they must never be committed.

    Create tests/stage-plugins.bats implementing the four behaviors above entirely against LOCAL git fixtures (`git init --bare` + a working clone with a trivial package.json/plugin.json committed and tagged inside `$BATS_TEST_TMPDIR`) — no real network, no real npm registry contact, $0.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| stage-plugins.py process → GitHub (network) | Fetches pinned, tagged source of third-party plugins |
| stage-plugins.py process → local filesystem (benchmarks/plugins/) | Materializes staged, pre-built code later loaded via `--plugin-dir` inside isolated claude sessions |
| Staged plugin's own build step → npm/node | Runs third-party install scripts (GSD: pure JS; context-mode: includes a native module) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02-06 | Tampering | git clone from a floating branch instead of a pinned tag | mitigate | requires an explicit `ref` in every git-type provisioning entry; clone is always `--branch <ref>`, never `main`/`HEAD`; a `.staged-ref` marker records the pinned ref actually cloned for audit |
| T-02-07 | Tampering | npm/pnpm install of third-party plugin dependencies (GSD's ajv/ajv-formats; context-mode's @modelcontextprotocol/sdk, better-sqlite3, zod) | mitigate | GSD approved in 02-RESEARCH.md's Package Legitimacy Audit (git-pinned, MIT, already a production dep of this repo), staged via lockfile-respecting `npm ci`; context-mode live-audited in this plan (19.3k stars, Elastic-2.0, actively pushed, already a declared production dependency of cairn's own plugin.json) — approved but staged best-effort only, since native-module compile availability is a sandbox capability, not a trust concern |
| T-02-08 | Denial of Service | an interrupted build leaves a broken half-staged directory | mitigate | clone-to-sibling-temp-dir-then-rename-on-success; `.staged-ref` is written only after every build/verification step succeeds, so a failed staging attempt never leaves something at the real staged_path that looks complete |
| T-02-SC | Tampering | npm/pip/cargo installs (transitively, GSD's + context-mode's real npm dependency trees) | mitigate | no blocking-human-verify checkpoint required — both source repos are fully audited (GSD in 02-RESEARCH.md; context-mode live-audited above) and are EXISTING production dependencies this repo already ships to end users, not new unvetted supply-chain surface introduced by the benchmark |
</threat_model>
