<objective>
Make environment isolation mechanical for every benchmark run: the `claude` subprocess Phase 1 launched with the operator's full, unscoped environment (the exact, already-measured cause of 45-62k cache-creation-token overhead) now receives an explicit, minimal `env={HOME, PATH, ANTHROPIC_API_KEY-if-present}` dict — and only that subprocess, never `verify.sh`. Purpose: FAIR-01 (isolation) + FAIR-02 (baseline manifests) are the two riskiest, highest-consequence pieces of this phase — get the mechanism right, prove it at $0 via bats, before anything else in the phase depends on it.
Output: `benchmarks/baselines/{vanilla,gsd-only,cairn}.json`, an extended `bench-run.py` with `isolated_claude_env()`/`load_baseline()`/required `--baseline`, and a bats suite that proves isolation and flag construction without spending a cent.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| bench-run.py process → `claude` subprocess | The arm under test; must receive only an explicit, minimal, allowlisted environment |
| bench-run.py process → `verify.sh` subprocess | The objective oracle; deliberately NOT isolated (needs the full inherited environment to run pytest/bats) |
| Baseline manifest JSON (file input) → cmd list construction | Untrusted-shaped input (a config file) feeding subprocess argv |
| `ANTHROPIC_API_KEY` (operator env var) → subprocess env passthrough | Must never be logged, echoed, or written to any file this repo commits |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02-01 | Tampering | baseline manifest fields (model/staged_path/plugin names) fed into cmd list | mitigate | cmd built as a Python list, never `shell=True`; every manifest value becomes one discrete argv element, never string-interpolated |
| T-02-02 | Information Disclosure | ANTHROPIC_API_KEY read from os.environ | mitigate | read at invocation time only, placed in the isolated env dict passed to `subprocess.run(env=...)`, never written to any committed file; bats asserts only boolean presence (`stub_observed_api_key_present`), never the literal value |
| T-02-03 | Tampering | staged_path pointing at an unpinned/mutable or nonexistent location | mitigate | `load_baseline()` validates every `staged_path` exists on disk before any subprocess is launched (EXIT_USAGE, fail loud); pinning to an immutable ref is Plan 02-02's job |
| T-02-04 | Information Disclosure | verify.sh subprocess inheriting the full, unscoped environment while claude's is scoped | accept | intentional per RESEARCH Pitfall 5 — verify.sh is the oracle, not the measured arm, and needs PATH-discoverable pytest/bats; unchanged from Phase 1's already-accepted behavior |
| T-02-05 | Elevation of Privilege | a `--plugin-dir` path pointing at attacker-controlled code executed inside the isolated session | accept | this phase's manifests point only at this repo's own trust boundary (cairn local path) or repos live-audited during planning (GSD, context-mode — see cairn.json's description); no user-supplied path is accepted at runtime |
| T-02-SC | Tampering | npm/pip/cargo installs of vendored plugin deps (GSD's ajv/ajv-formats; context-mode's real npm tree) | mitigate | both source repos are already fully audited (GSD in 02-RESEARCH.md's Package Legitimacy Audit; context-mode live-audited during this phase's planning — 19.3k stars, Elastic-2.0, actively pushed, already a declared production dependency of cairn/.claude-plugin/plugin.json); no `[ASSUMED]`/`[SUS]` packages in scope — actual install execution and its own supply-chain discipline (`npm ci`) is Plan 02-02's concern |
</threat_model>
