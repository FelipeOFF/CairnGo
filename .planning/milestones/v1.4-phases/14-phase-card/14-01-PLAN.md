<objective>
Every `phases[]` entry in `cairn-status.py --json` gains four additive fields —
`purpose`, `research_done`, `issues_done`/`issues_total`, `verify_status` — so
the phase card (Plan 14-02) has real data to render instead of guessing. This
plan is data-layer only: no terminal or HTML rendering changes yet, proven
entirely through `--json`.

Purpose: CARD-01 requires every card to name what the phase is FOR; CARD-02
requires it to say whether research happened, how many plans/issues are
done, and the verification verdict. None of that data exists in
`phase_model()` today — `roadmap_phase_rows()` only reads the ROADMAP's
checkbox/table section, never the prose `### Phase N:` detail blocks where
`**Card:**`/`**Goal:**` actually live, and `phase_model()` never looks at
`NN-RESEARCH.md`, counts issues by phase, or reads `NN-VERIFICATION.md`'s
frontmatter.
Output: `cairn/scripts/cairn-status.py` with four new per-phase JSON keys;
`tests/cairn-phase-card.bats` proving each one via `--json`.
</objective>
