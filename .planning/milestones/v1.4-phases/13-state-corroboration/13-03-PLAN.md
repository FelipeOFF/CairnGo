<objective>
Give `/cairn:doctor` two new capabilities: a corroboration check that reads
Plan 13-01's verdict for every phase and routes each conflict to a
recommended fix (CORR-06), and a `--link-refs` backfill that recovers the
bd-issue-to-PR linkage on already-closed issues from this repo's existing git
history without rewriting a single commit (CORR-08's backfill half).

Purpose: corroboration that only a machine can see is not corroboration a
human acts on — doctor is where every other `cairn-status` divergence already
gets an itemized, routed report (the `--close-completed`/`--fix-labels`
pattern). CORR-08 exists because zero of this repo's 239 commits carry a bd
id today; the fix has to work on history that already happened.
Output: doctor checks 11 and 12, both read-only by default, both following
the established fixer-flag convention.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git commit subjects → `--link-refs` correlation | Commit messages are attacker-influenceable in a public repo (a crafted PR title could contain a fake `(#N)`); the unambiguous-match-only rule (never guess, never write on ambiguity) bounds the blast radius of a spoofed subject to "no link written", never a wrong link silently accepted |
| `cairn-status.py --json` subprocess output → doctor check 11 | Same trust level as every other doctor check already shelling to another cairn script; parsed defensively (JSON decode failure degrades to WARN, never a crash) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-07 | Tampering | crafted `(#N)` in a commit subject misattributing a PR to an issue | low | mitigate | correlation requires an EXACT, UNAMBIGUOUS single-candidate match within a narrow time+pathspec window; any ambiguity is reported, never written |
| T-13-08 | Denial of Service | `--link-refs` issuing one `bd update` per candidate issue | low | accept | bounded by the number of closed issues lacking an external_ref, one-time backfill operation, same cost class as `--close-completed`'s existing bulk-close loop |
| T-13-09 | Repudiation | doctor check 11 silently passing when `cairn-status.py --json` itself errors | medium | mitigate | subprocess failure/unparsable JSON is explicit `"warn"` with a stated reason, never collapsed into `"ok"` |
</threat_model>
