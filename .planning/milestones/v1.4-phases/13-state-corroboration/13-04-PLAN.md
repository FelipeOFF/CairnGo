<objective>
Give the ship gate — `cairn-gate.py` (the `/cairn:ship` path) and
`cairn/capability/scripts/cairn-loop-gate.py` (the plain `/gsd:ship` path via
the GSD capability) — one additive, in-lockstep block reason: a phase the
ROADMAP marks complete whose directory holds nothing built at all
(`disk_state == "none"`), independent of what bd says. Both scripts gain the
identical check in this same plan; neither ships without the other (D-10).

Purpose: the EXISTING gate already blocks on "non-closed bd issue in a
completed phase" — but a phase can be marked complete AND have zero open bd
issues (nobody ever created any) while nothing was actually built. That gap
is exactly what CORR-05 exists to close, and a gate that passes while its
capability-bundle twin blocks (or vice versa) is the same class of silent
lie this whole milestone exists to remove.
Output: an additive, twin-locked block reason in both ship-gate entry points,
verified independently in each script's own bats suite.
</objective>
