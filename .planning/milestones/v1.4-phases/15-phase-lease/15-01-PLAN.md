<objective>
Build the phase lease itself: a dedicated bd issue per phase, acquired and
released the same way cairn already claims and releases per-plan issue
claims — `bd update --claim` / `bd update --assignee "" --status open` — one
level up (D-01). Identity is the acquiring worktree's absolute path (D-02,
measured live this session: `git rev-parse --show-toplevel` differs per
worktree while bd's own actor resolution does not). Staleness is a 4-hour
heartbeat TTL (D-03), never a process-liveness check, because every
`/cairn:*` invocation is a separate short-lived process with nothing alive
for the whole duration of a phase.

Purpose: today the only concurrency primitive is the per-issue claim, which
`execute-wave-pre.md` already documents failing at: "if an id is claimed by
another, don't steal it — surface the conflict and continue," discovered
late and id by id. This plan gives every phase ONE thing to check, once, up
front.

Output: `cairn-lease.py` / `cairn-lease.sh`, fully working `acquire`,
`release` (single-phase and `--mine`), `renew`, and `status` (single-phase
and `--all`), with a real two-worktree end-to-end test proving LEASE-03's
exact claim.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bd issue metadata (`metadata.cairn.lease.*`) | Externally-writable JSON — any bd-authorized actor (human, script, a future integration) can set it directly via `bd update --metadata`, bypassing this module entirely |
| worktree-path identity | Derived from `git rev-parse --show-toplevel`, itself derived from the local filesystem layout — not a security credential, purely a coordination signal |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-01 | Tampering | `metadata.cairn.lease` read by acquire()/status()/renew() | medium | mitigate | every read defensively `isinstance`-checks (mirrors `gsd_req()` in cairn-doctor.py); a malformed or non-dict value degrades to "vacant", never a traceback, and `release <N>` remains available regardless of what the field contains — no crafted metadata can create a permanent block |
| T-15-02 | Denial of Service | a forged `heartbeat_at` set far in the future would read as perpetually live | low | accept | the lease is advisory only (D-04 — acquire() only warns, it never blocks execution) and `release <N>` is unconditional and ignores heartbeat entirely, so a human always has an unconditional escape hatch; a forged timestamp degrades UX, never availability |
| T-15-03 | Spoofing | two worktrees on the SAME machine share bd's own actor resolution and are indistinguishable by it | low | accept | documented, known, accepted limitation (D-02) — outside this phase's target scenario (worktree-per-agent); the worktree-path identity this module uses is exactly the mitigation for the actual scenario (cross-worktree on one repo) |
</threat_model>
