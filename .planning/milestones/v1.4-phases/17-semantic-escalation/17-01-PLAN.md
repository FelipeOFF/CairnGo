<objective>
Build `cairn-reconcile.py`, the deterministic, provably-write-free core of the
semantic escalation pipeline (D-01's first layer): a `collect` subcommand that
gathers the evidence a later investigation reads, gated so it only ever runs
on a phase corroboration has already marked `conflict` (ESC-04), and a
`verify` subcommand that mechanically re-checks a proposal's citations
against the real files they claim to quote (D-03), rejecting the whole
proposal on any mismatch.

Purpose: this is the layer the roadmap's own success criterion 1 names
directly — "um grep sobre o caminho de análise não encontra nenhum verbo de
escrita do bd, e um teste roda esse caminho contra um fixture e afirma que
nada mutou." A tool-restricted subagent (built in 17-02) is a strong
guarantee too, but it lives in the harness, not in a file anyone can grep or
run against a fixture. This script is what makes that guarantee inspectable.

Output: `cairn/scripts/cairn-reconcile.py` + `.sh` wrapper (the `collect` and
`verify` subcommands only — the subagent and the `/cairn:reconcile` command
that orchestrates them are Plan 17-02; `cairn-doctor.py --apply-reconciliation`
is Plan 17-03), `tests/cairn-reconcile.bats`, and a `.gitignore` entry for the
new evidence-bundle file.
</objective>

**Proposal schema this plan's `verify` subcommand consumes** (defined here so
Plans 17-02 and 17-03 write/read the identical shape — Claude's Discretion
per CONTEXT.md, fixed once, here, for consistency across plans):
```
{
  "phase": <int>,
  "generated_at": <iso8601>,
  "evidence_hash": "sha256:<hex>",
  "claims": [
    {
      "statement": "<the claim in prose>",
      "citations": [
        {"file": "<repo-relative path>", "line": <int>, "text": "<exact literal line text>"}
      ],
      "recommended_action": {"type": "bd_close"|"bd_reopen"|"manual_review", "issue": "<bd id>"|null, "reason": "<str>"|"note": "<str>"}
    }
  ]
}
```
`verify` operates on this shape (or a `--file <path>` override for testing);
it never needs `recommended_action` to run its own check — only `citations`.

**Evidence bundle schema `collect` produces** at `.cairn/reconcile-evidence.json`
(and under `--json` prints to stdout too):
```
{
  "phase": <int>,
  "generated_at": <iso8601>,
  "evidence_hash": "sha256:<hex>",
  "corroboration": {"verdict": "conflict", "evidence": {...}, "conflicts": [...]},
  "journal": {"last_moved": {...}, "history": [...]},
  "git_log": [{"hash":..., "date":..., "author":..., "subject":...}],
  "git_shallow": <bool>,
  "roadmap_excerpt": "<phase's ROADMAP.md section text>",
  "context_excerpt": "<phase's NN-CONTEXT.md text, or null if absent>"
}
```
`evidence_hash` = sha256 over `json.dumps(bundle, sort_keys=True)` computed
**excluding** `generated_at` and `evidence_hash` itself (the only two fields
that would otherwise make the hash non-reproducible run-to-run against
unchanged sources) — this is what makes the "two consecutive collects ->
identical hash" must-have true, and what Plan 17-02's cache-hit check relies
on.

  <behavior>
    - `verify <N> [--file PATH] [--json] [--project-dir DIR]`: reads the
      proposal (default `.cairn/conflicts.json`, `--file` overrides — this
      is what makes the task bats-testable without a real subagent ever
      running) and asserts `proposal["phase"] == N` (mismatch -> EXIT_USAGE).
    - Flattens every `citations[]` entry across every `claims[]` item (D-03:
      the check is over every citation in the proposal, not just the first
      one that fails). For each citation: open `citation["file"]` (resolved
      relative to `--project-dir`/cwd), read it as lines, and compare
      `lines[citation["line"] - 1].rstrip("\n")` (1-indexed, matching how a
      human reads a line number) against `citation["text"]` **exactly**
      (D-03 rejected a hash of the trimmed text specifically for being
      whitespace-blind and unreadable to a human reviewer — so this
      comparison is exact-string, not normalized). A missing file, an
      out-of-range line, or a text mismatch are all "this citation failed"
      — no partial credit, no "close enough".
    - **The moment any single citation fails, the WHOLE proposal is
      invalid** — do not report "3 of 4 claims verified"; report which
      citation(s) failed and that the entire proposal is rejected. This is
      D-03's explicit rule: "uma citação que não bate invalida a proposta
      inteira... uma proposta com uma citação falsa não é uma proposta com
      um erro, é uma proposta em que não se pode confiar."
    - `--json` prints `{"valid": bool, "phase": N, "failed_citations": [...]}`
      (each failure naming file/line/expected-text/actual-or-error); human
      mode prints one line per failure, or "[cairn-reconcile] N citation(s)
      verified, proposal valid" when all pass.
    - `EXIT_OK=0` (valid), `EXIT_INVALID_PROPOSAL=4` (one or more citations
      failed — a new, script-specific code, documented in the docstring).
    - Same zero-bd-write-verb guarantee as Task 1 — this subcommand only
      ever opens files for reading.
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| conflicts.json (proposal) -> verify() | An untrusted/possibly-hallucinated LLM proposal is the input to a mechanical check; verify() must never trust it without re-reading the cited files itself |
| local filesystem -> collect()'s git/bd/journal reads | All reads are local and already-trusted (no network, no untrusted remote input) — the only real risk is a bug in collect() itself gaining write capability by accident |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-01 | Tampering | cairn-reconcile.py collect | high | mitigate | Zero bd/journal write-verb code paths (Task 1's behavior spec); proven by grep AND a bats mutation test, not by convention alone (ESC-02) |
| T-17-02 | Spoofing | verify()'s citation check | medium | mitigate | Exact file+line+literal-text re-read (D-03), never trusting the proposal's own claim about what a file contains; one bad citation invalidates the entire proposal, closing the "mostly-true proposal slips through" gap |
| T-17-03 | Denial of Service | collect()'s git log gathering | low | mitigate | git log capped at 50 commits per pathspec; a shallow clone flags `git_shallow: true` rather than looping or erroring |
| T-17-04 | Information Disclosure | evidence bundle contents | low | accept | `.cairn/reconcile-evidence.json` is local, gitignored, and contains only already-in-repo/already-in-bd text (no secrets fetched from elsewhere) |
