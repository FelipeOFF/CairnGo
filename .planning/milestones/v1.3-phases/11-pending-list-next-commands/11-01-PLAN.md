# Phase 11 Plan 01 — say what is pending, and what to run next

## Why

The board answers "what tracked work exists". It has never answered "which
phase should I run, and why that one" — the question that actually decides what
happens next. Phase 10 made the data readable; this renders it.

## Tasks

1. **`pending_phases()` / `next_commands()`** beside the model, so both
   surfaces render identical strings. Reasons are generated from the graph:
   what blocks this phase, or what waits on it.

2. **Fix the dependency semantics.** A dependency is satisfied by the work
   being done, not by the roadmap checkbox being ticked — otherwise a verified
   phase keeps everything behind it reading "waits on 10".

3. **Terminal panel** under the footer: pending phases with title, state, plan
   progress and what they wait on; then the commands, the runnable one in the
   page's accent and blocked ones set back.

4. **HTML panel**, two columns on a desktop and stacked below 760px, matching
   the page's existing language — same head shape as a lane, one chamfered
   corner, mono only for data.

5. **Tests**, including the cross-surface proof that the terminal and the HTML
   carry the same commands *and* the same reasons.

## Verification

- `bats tests/cairn-phase-model.bats` green.
- `bats tests/cairn-status.bats` green — the existing board contract is intact.
- Rendered and measured in a real browser: no horizontal scroll, columns on one
  baseline, titles on one vertical line, nothing clipped by the chamfer, and
  every new text token at or above 4.5:1 against the actually painted pixel.
