# Fase 25 Plano 07 — o prompt do doctor aprende o quarto estado

## O defeito, com a medição que o abriu

`cairn/commands/doctor.md` é o prompt que o agente lê para explicar o
`/cairn:doctor` ao operador. Medido neste worktree em 2026-08-07, contra o
`cairn-doctor.py` do `b9fdfb3`:

```
$ python3 cairn/scripts/cairn-doctor.py --json | jq '[.checks[].id] | length'
21
$ python3 cairn/scripts/cairn-doctor.py | tail -1
[cairn-doctor] FAIL — 16 ok, 1 not-applicable, 3 warning(s), 1 failure(s)
```

E o prompt, na linha 25, ensina `one ✓/⚠/✗ line per check` — **três** símbolos.
O `⊘` não aparece nele, `not-applicable` não aparece, `INCOMPLETE` não aparece,
`no-input`/`out-of-scope` não aparecem. Cruzando os 21 ids do `--json` contra o
texto do prompt, **12 não têm tratamento nenhum**:

```
bd-version, gsd-capability, phase-corroboration, phase-artifacts, external-ref,
lease-stale, release-versions, test-parallel, req-ledger, response-language,
phase-landed, plan-counters
```

O script diz a verdade e o prompt ensina o agente a traduzi-la para um
vocabulário de três estados que não tem onde encaixar o quarto: o verde falso
volta pela conversa depois de ter sido removido do código.

## O que o script realmente diz (medido, não suposto)

| Fato | Onde | Valor |
|---|---|---|
| Vocabulário de status | `cairn-doctor.py:614` | `{"ok": "✓", "not-applicable": "⊘", "warn": "⚠", "fail": "✗"}` |
| Famílias do quarto estado | `cairn-doctor.py:604-605` | `out-of-scope` (permanente, não torna o relatório incompleto) e `no-input` (lacuna fechável) |
| Veredito | `cairn-doctor.py:3502-3508` | `FAIL` se há falha; senão `INCOMPLETE` se há `no-input`; senão `ok` |
| Chaves do topo do `--json` | medido | `ok`, `failed`, `applicable`, `counts`, `note`, `active_phase`, `milestone` — **não existe** chave `verdict` |
| Código de saída | `cairn-doctor.py:3512` | `0` mesmo com `INCOMPLETE`; `7` só com falha |

Consequência para o prompt: quem lê o `--json` **deriva** o veredito de duas
chaves booleanas — `failed` → FAIL; `failed:false` com `ok:false` → INCOMPLETE;
as duas → ok. Nenhum número entra nessa regra.

## A decisão de projeto: rotear por endereço, não por cópia

O critério de aceitação pede que todo id reportado pelo `--json` tenha
tratamento. Há duas formas de conseguir isso:

1. copiar as 21 entradas de remediação para dentro do prompt;
2. o prompt nomear a **única** tabela de roteamento que já existe e é completa.

Medido: `cairn/docs/commands/doctor.md` já carrega entrada para **21 de 21**
ids, com símbolo, família de `not-applicable` e a ação de cada um. E o plugin
instalado embarca essa página — verificado em
`~/.claude/plugins/cache/cairngo/cairn/1.5.0/docs/commands/doctor.md`.

A saída 1 cria uma segunda lista à mão que precisa concordar com a primeira, e
este repositório tem **cinco** precedentes medidos de exatamente isso
envelhecer (o último: dois números à mão discordando dentro do mesmo arquivo),
enumerados no cabeçalho de `tests/cairn-command-surfaces.bats`. A saída 2 não
tem como divergir: há um autor por fato.

Some-se o contexto desta fase: o número de checagens está subindo de 21 para 22
pela outra frente **agora**. Um prompt com a lista copiada nasceria errado no
merge; um prompt que endereça a tabela continua correto, e o teste passa a
cobrar a entrada de quem acrescentou a checagem — que é onde a cobrança
pertence.

**Por isso o prompt não escreve a contagem de checagens em lugar nenhum.**

## Tarefas

### T1 — o teste que reproduz o defeito, antes do conserto

Arquivo novo `tests/cairn-command-surfaces.bats` (as superfícies de prompt não
têm par `.py`, então não cabem no `tests/<basename>.bats` de um script).
Asserções:

1. o prompt nomeia os quatro símbolos e as quatro palavras de status;
2. o prompt nomeia `INCOMPLETE` e as duas famílias (`no-input`,
   `out-of-scope`);
3. o prompt diz que `INCOMPLETE` não muda o código de saída;
4. o prompt nomeia a tabela de roteamento (`docs/commands/doctor.md`);
5. **todo id que o `--json` reporta tem entrada nessa tabela** — os ids vêm de
   uma execução real do `cairn-doctor.py --json`, nunca de uma lista escrita no
   teste;
6. o prompt **não** escreve contagem de checagens (guarda dos seis
   precedentes): nenhum numeral nem numeral por extenso ligado a "checks".

As asserções 1-4 e 6 são vermelhas contra o `b9fdfb3`. A 5 já é verde hoje — é
a invariante que sustenta o endereçamento, e é ela que a quebra guardada de T3
prova ser real.

### T2 — o conserto

`cairn/commands/doctor.md`:

- passo 1: acrescenta que `INCOMPLETE` sai com `0`, e por quê;
- passo 2: reescrito para os quatro estados, as duas famílias, a derivação do
  veredito pelas duas chaves booleanas, e a regra de nunca relatar como limpa
  uma corrida com `⊘ no-input`;
- passo 5: mantém o roteamento **acionável** aqui (o que este comando oferece:
  `--fix-labels`, `--close-completed`, regenerar mapa) e endereça a tabela
  completa para o resto, com a proibição de copiá-la.

### T3 — a quebra guardada

Remover uma entrada de id da tabela de roteamento e provar a asserção 5
vermelha; restaurar de cópia `cp` (nunca `git checkout`). A asserção derrubada
vai para o SUMMARY.

## Fora de escopo

`cairn/docs/commands/doctor.md` é da outra frente nesta fase e **não é
editado** — nem para a quebra guardada, que restaura por `cp`.
