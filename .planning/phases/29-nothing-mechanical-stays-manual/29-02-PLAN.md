As duas últimas peças do "um comando" são trabalho de outros scripts, e é assim que
elas devem continuar: `close <N> --apply` **invoca**, não reimplementa.

**Mapa.** `cairn-map.py <N> --json`, por subprocess, com o `--planning-dir` do
próprio invocador. Nada do mecanismo de marcadores é reimplementado — ele já refuta
arquivo com marcador solto e já é idempotente. O `changed` do JSON dele entra no
relatório.

**Lease.** `cairn-lease.py release <N> --json`. Liberar lease não-mantido é no-op
lá; não replique a conta de TTL aqui — duas contas de staleness que podem discordar
é a doença deste milestone com outra roupa.

**O `bd` ausente recusa antes de escrever, não no meio.** `shutil.which("bd")` é
checado **antes** da primeira escrita: sem `bd`, exit 5 e os três arquivos ficam
byte a byte iguais. Bookkeeping pela metade é exatamente o estado que esta fase
existe para remover, e o 5 é o código de indisponibilidade da casa — nunca falha de
checagem. Quem quiser só a cirurgia de arquivo passa `--no-tracker`: pula mapa e
lease, escreve os três arquivos, exit 0, e o relatório diz o que não rodou.

**Os dois pontos de consumo da config do plano 29-03**, lidos por subprocess ao
`cairn-config.py` no formato defensivo do `fetch_lease_status()`:

  - `bookkeep.auto_commit` — quando `true`, depois de tudo aplicado, `git add` dos
    arquivos efetivamente alterados (a lista que o próprio comando planejou, nunca
    `git add -A`) e um commit `chore(cairn): bookkeeping fase N`. Quando `false`
    (o default), nada é commitado e o relatório diz que os arquivos ficaram sujos e
    qual é o comando de commit. Falha de git é reportada, não fatal: as edições já
    estão no disco e o commit é conveniência.
  - `ship.pr_scope` — vira o campo `pr_due` do relatório: `true` com `"phase"`,
    `false` com `"milestone"` (a PR sai no fim do ciclo) e `false` com `"none"`. É
    onde a decisão importa: fim de fase.

**Testes, com a quebra de cada um:**
  - com `bd` no PATH e um fixture com lease adquirido para a fase: depois do
    `--apply`, `cairn-lease.py status N --json` reporta vago, e o `NN-BEADS-MAP.md`
    foi regenerado. Quebra: pular o shell-out deixa o lease preso — o defeito
    concreto que fecha fase à mão produz;
  - `PATH` sem `bd`: exit 5 e sha256 dos três arquivos inalterado. Quebra: escrever
    primeiro e descobrir depois;
  - `--no-tracker` sem `bd`: exit 0, arquivos escritos, relatório nomeando o que não
    rodou. Quebra: um pulo silencioso;
  - `auto_commit=true` num repo git limpo: `git log` tem um commit novo tocando
    exatamente os arquivos planejados; com `false`: zero commits novos e árvore
    suja. Quebra: ignorar a config — as duas metades do mesmo teste, uma para cada
    valor;
  - `pr_scope` em `milestone` dá `pr_due:false` e em `phase` dá `pr_due:true`.
    Quebra: campo constante.

Atualize o cabeçalho do `cairn-bookkeep.sh` em lockstep com os `EXIT_*` — a
CONVENTIONS.md pede que o leitor nunca precise abrir o `.py` para saber o que um
código significa.
