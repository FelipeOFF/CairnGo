<objective>
Build the corroboration engine at the root of milestone v1.4: `phase_model()` in
`cairn/scripts/cairn-status.py` gains additive per-phase evidence from four
independent sources (disk, bd, the ROADMAP checkbox, STATE.md's `active_phase`),
a three-state verdict (`ok` / `conflict` / `unknown`), and an itemized conflicts
list carrying a `blocks` or `informs` severity — never a fifth `disk_state`
value, never a majority vote, and never a silent "ok" when a source could not
be read.

Purpose: this is the literal fix for the milestone's root cause — a phase's
state currently comes from checking whether four filenames exist, never
opening them, never asking bd. Every other plan in this phase (rendering,
doctor, the ship gate) and every later phase in the milestone (14-17) reads
from what this plan produces. This plan also delivers ROADMAP success
criterion 4's second half directly: `/cairn:autonomous` reads
`cairn-status.py --json`'s `next_commands[]` to pick its next phase
(`cairn/commands/autonomous.md` step 0.3 — "Start at $ARGUMENTS when given,
else at the first entry of next_commands"), so making that computed list
itself skip a conflicting phase is the self-contained fix, at the one model
every consuming surface already reads from — not a second command learning
about corroboration on its own.
Output: `bd_state()`, `corroborate()`, `phase_model()`'s additive keys,
`phase_next_command()`'s conflict guard, `next_commands()`'s conflict
reroute, and `main()`'s bd-unreachable degrade path (proven across all
three of its render paths) — verified end-to-end via `cairn-status.sh`, not
read from the code.
</objective>
