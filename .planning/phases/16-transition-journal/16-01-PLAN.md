<objective>
Build cairn-journal.py: the single append-only, local, gitignored writer for
cairn's own observed state history (D-02) — scoped to exactly three
categories (D-01): phase-state axis transitions (disk/bd/roadmap/state_md,
the same four evidence axes `corroborate()` already computes in
cairn-status.py), lease acquire/release, and corroboration verdict changes.
Never everything cairn does (map regen, doctor runs, arbitrary bd actions)
— that would drown the signal, per D-01's rejected alternative.

Purpose: JOUR-02 needs to say "when did each side last move," which means
the journal has to have SEEN the side that moved — a disk-vs-bd conflict is
born from an issue closing or a lease changing hands, neither of which is a
phase-directory-artifact transition on its own. This plan builds the writer
and its two read surfaces (`history` for post-mortem, `last-moved` for the
doctor's conflict report in a later plan); wiring the actual callers
(cairn-lease.py, cairn-status.py, cairn-doctor.py) is later plans' work —
this plan's own tests exercise the CLI directly, not through those callers.

Output: `cairn-journal.py` / `cairn-journal.sh`, with `observe` (batched,
diff-then-append), `lease` (unconditional append — dedup is the CALLER's
job, see Plan 16-03/16-04), `history`, and `last-moved` all working, plus
the byte-offset torn-line quarantine test that proves JOUR-04.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-16-01 | Tampering | `observe`'s stdin JSON parsing | medium | mitigate | malformed JSON, a non-array top level, or an element missing `phase` all die with EXIT_USAGE and a clear message rather than a traceback or a partial/garbled append; the array is read once into memory (never streamed line-by-line as executable input), so a crafted payload cannot inject anything beyond well-typed dict values into the record schema |
