<objective>
Wire cairn-status.py's `phase_model()` to call `cairn-journal.py observe`
once per invocation, batching every phase's evidence+verdict in a single
stdin-JSON payload, right after `corroborate()` has already produced its
answer for every phase in the loop (Plan 16-01's design point: "the path
that computes the corroboration verdict" per D-01/D-02).

Purpose: this is where JOUR-01's "phase state" and "corroboration verdict"
categories actually get observed in practice — every surface that renders
the board (terminal, `--json`, `--html`) and every doctor check that
shells out to `cairn-status.py --json` funnels through this ONE function,
so wiring here reaches all of them with no new call site, exactly the
"one function, all surfaces" precedent phase 13/14 already established.

This plan also carries JOUR-03's own proof obligation, because it is the
ONLY plan that touches the corroboration computation's call graph at all:
`corroborate()` itself is not modified by this plan (or any plan in this
phase) — it keeps reading disk/bd/roadmap/STATE.md live, exactly as phase
13 built it. The test this plan adds exists to PROVE that fact
mechanically, not narrate it, because Pitfall 11 (PITFALLS.md) names this
exact failure shape as the milestone's own root bug, relocated to a new
file, as the single most likely way this phase could go wrong quietly.

Output: `phase_model()` observes every phase's corroboration result into
the journal, resiliently; a test that deletes the journal and diffs
`cairn-status.py --json`'s own output before/after, byte-for-byte.
</objective>
