<objective>
`/cairn:doctor` gains a check that names which artifact is missing when a
phase's board row would otherwise show only a dash — the doctor half of
D-04's narrowing of the phase card's missing-artifact story (the board shows
a plain dash for a phase with nothing yet; an UNEXPECTED absence, like a
plan lacking its summary or a verification file with no readable verdict, is
what doctor names).

Purpose: ROADMAP's success criterion 3 for this phase ("a phase missing an
artifact says which one, instead of the absence reading as absence of
information") is deliberately NOT the board's job past a bare dash — it is
doctor's, the same division of labor Phase 13 already established for
per-source conflict detail. This plan is that half.
Output: `check_phase_artifacts()` wired into `cairn-doctor.py`'s check list;
bats coverage proving it names both failure shapes and never fails the run.
</objective>

    Add `check_phase_artifacts(root, planning_dir, disk_reasons)` near
    `check_phase_corroboration()`, following its docstring shape (what it
    checks, its check id, why its severity policy is what it is). Build
    `items` in two passes, both `warn`-only:

    First, from the ALREADY-COMPUTED `disk_reasons` dict (do not call
    `disk_incomplete_reasons()` again): for every `(n, reason)` in
    `sorted(disk_reasons.items())`, append `f"phase {n}: {reason}"`. This is
    deliberately UNGATED — unlike check 5, which only surfaces a
    `disk_reasons` entry when that phase is also roadmap-complete with an

    `check_phase_corroboration()` already does (same `subprocess.run([...,
    "--json", "--planning-dir", str(planning_dir)], ...)` call, same
    `returncode not in (0, 5)` and JSON-decode-failure degrade to a single
    extra `warn` item noting the verify-status half of this check could not
    run — never crash the whole check over a subprocess hiccup, mirroring
    `check_phase_corroboration()`'s own degrade). On success, for each `p`
    in `data.get("phases") or []`: if `p.get("disk_state") == "verified"`
    and not `p.get("verify_status")`, append `f"phase {p['number']}: has a
    VERIFICATION.md but no readable 'status:' field in its frontmatter"`.

    Return `{"id": "phase-artifacts", "status": "warn" if items else "ok",
    "detail": (f"{len(items)} phase(s) with an unexpected missing/unreadable
    artifact" if items else "every phase's artifacts are complete and
    readable"), "items": items}`. Document in the docstring, explicitly,
    that this check's status is NEVER `"fail"` — a deliberate choice
    distinct from `phase-corroboration`'s `blocks`/`fail` behavior, because
    a missing SUMMARY or an unreadable verdict is a record-hygiene gap, not
    contradictory evidence about what actually happened (D-01's "cairn never
    stops the flow" applied to hygiene, not correctness, findings).

    Wire it into `main()`'s `checks = [...]` list, passed `(root,
    planning_dir, disk_reasons)` — `disk_reasons` is already a local
    variable in `main()` by the time the list is built, so this is a
