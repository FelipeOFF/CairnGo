# Fase 25 Plano 05 — o cairn-parallel para de reter e para de derivar

## Por que estes dois vêm juntos

Os dois moram no `cairn-parallel.py` e os dois são a mesma classe de erro: uma
**identidade** que o script deriva de um estado que muda por baixo dele.

- O `rhq` deriva "este worktree tem trabalho que o git não recria" de um
  `git status` que passou a incluir um artefato cuja perda não muda veredito
  nenhum.
- O `r4g` deriva o nome da branch de uma fase de um diretório que pode nascer
  **depois** da branch.

## CairnGo-rhq — o journal retém todo worktree que journaliza

Medido ao fechar a fase 28, e a armadilha fecha dos dois lados:

```
sem commitar a partição -> reason: uncommitted changes (git cannot recreate these)
commitando a partição   -> reason: carries commits HEAD lacks
```

Só fica `removable` depois de commitada **e** mesclada, e nada no fluxo do cairn
faz nenhuma das duas.

### A decisão (D-05), já tomada

Das três saídas, **excluir `.cairn/journal/` da checagem de trabalho não
commitado**, e a defesa é o `DJOUR-03`: o journal é o único artefato do cairn
cuja perda **não muda veredito nenhum**, e é precisamente por isso que ele não
pode reter um worktree. Reter é o que se faz com trabalho que o git não consegue
recriar; o journal não é isso.

### A armadilha da implementação, medida antes de escrever a condição

O filtro ingênuo — descartar linhas cujo caminho começa com `.cairn/journal/` —
é **inerte** com a chamada de hoje. Medido em repositório de teste, com o mesmo
`.gitignore` deste projeto (`.cairn/journal/*` mais `!.cairn/journal/*.jsonl`):

```
$ git status --porcelain              # o que worktree_dirty() chama hoje
?? .cairn/                            <- o DIRETÓRIO, colapsado

$ git status --porcelain -uall
?? .cairn/journal/-0001.jsonl         <- o arquivo, e só agora o filtro casa
```

Com `-u normal` o git colapsa um diretório inteiramente não rastreado numa linha
só, e `.cairn/` não casa com `.cairn/journal/`. Então a chamada passa a
`--porcelain -z -uall`:

- `-uall` para que o caminho exista para ser filtrado;
- `-z` para que o caminho venha cru, sem aspas nem escape, e para que uma
  renomeação venha em dois campos em vez de um `->` no meio da linha.

Um worktree cujo único conteúdo não rastreado é o journal fica **limpo**. Um
worktree com qualquer outra coisa continua sujo, arquivo por arquivo — a
expansão do `-uall` não perde nenhum, ela nomeia mais.

A postura de degradação não muda: `git status` ilegível continua retendo. O que
não se pode medir não se remove.

## CairnGo-r4g (FIX-02) — a branch da fase deriva quando o diretório aparece

Medido ao vivo na v1.4: `batch --json` devolveu `slug: null` e `branch:
phase/19` para a fase 19, que ainda não tinha diretório. Depois que
`.planning/phases/19-*` existe, a mesma fase resolveria `phase/19-<slug>`.

O caminho da worktree (`<root>-phase-N`) não muda, e o `reconcile` descobre por
`refs/heads/phase/*`, então nada quebra hoje — mas **duas branches para a mesma
fase são possíveis**: apagada a worktree, o `prepare` recusa uma branch de mesmo
nome sem worktree (`cairn-parallel.py:972`) e **não recusa a de nome novo**, que
é exatamente o caso que o slug tardio produz.

### O conserto: a identidade vem de quem já existe, em três degraus

`phase_layout()` deixa de derivar o nome sempre e passa a **adotar** o que já
existe, na ordem em que a evidência é forte:

1. **o worktree canônico** registrado em `<root>-phase-N` — a identidade que o
   próprio issue nomeia como estável — e a branch é a que o git diz que está lá;
2. senão, **exatamente uma** branch `refs/heads/phase/N…` — a que o `prepare`
   deu;
3. senão (nenhuma, ou mais de uma sem worktree canônico), deriva do slug, como
   hoje.

E o resultado passa a carregar `branch_source` (`worktree` / `existing-branch` /
`derived`), porque uma superfície que escolhe entre três fontes e não diz qual
usou é a forma de mentira que esta fase inteira persegue.

**Por que o degrau 3 não morre com ambiguidade**, apesar da regra da casa de
nunca "pegar a primeira": duas branches para uma fase é o estado **normal** de
uma fase dividida entre duas frentes — este repositório tem `phase/25-tools` e
`phase/25-surfaces` agora, medido. Morrer ali derrubaria o `batch` inteiro por
causa de uma fase. O degrau 3 mantém byte a byte o comportamento de hoje
(critério 3 / D-07) e o `branch_source` diz que a escolha foi derivada.
