<interfaces>
<!-- aggregated.json's exact shape, from benchmarks/scripts/bench-aggregate.py — bench-chart.py's ONLY input. Use directly, no exploration needed. -->

Top-level shape: `{"cells": {"<task_id>::<baseline_id>": {...}, ...}, "rejected_rows": <int>}`.

Per-cell shape (from `cell_stats()` in `bench-aggregate.py`):
```
{
  "task_id": str, "baseline_id": str, "category": str|null,
  "n_total": int, "n_passed": int, "pass_rate": float (0.0-1.0),
  "cost_median": float|null, "cost_min": float|null, "cost_max": float|null, "cost_iqr": float|null,
  "tokens": {
    "input_sum": int, "input_median": float|null,
    "cache_creation_sum": int, "cache_creation_median": float|null,
    "cache_read_sum": int, "cache_read_median": float|null,
    "output_sum": int, "output_median": float|null
  }
}
```
`cost_median`/`tokens.*_median` are `null` (never a fabricated `0`) exactly when `n_passed == 0` for that cell — this is the honesty signal `bench-chart.py` must render as "no data", never as a zero-height bar. `cells` iterates in sorted `"task_id::baseline_id"` key order in the source file (written via `json.dumps(sort_keys=True, ...)` by `bench-aggregate.py`) — `bench-chart.py` must preserve this same sorted-key order when iterating for its own determinism.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `aggregated.json` (produced upstream by `bench-aggregate.py` from JSONL rows ultimately rooted in `task.json` ids + `claude -p` JSON output) -> `bench-chart.py` -> SVG text content, later rendered by a browser/GitHub | Task/baseline/category strings are repo-controlled today, but the boundary artifact is regenerated on every run, so a future contributor's `task.json` edit is an untrusted-relative-to-this-script input the chart renderer must not trust blindly |
| `--label` CLI argument -> SVG caption text | Operator-supplied string, rendered verbatim (only escaped) into the document |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-06-01 | Tampering | `bench-chart.py` SVG text-node rendering of `task_id`/`baseline_id`/`category`/`--label` | mitigate | Every interpolated string passes through one shared `xml_escape()` helper before being placed in any SVG text node or attribute — proven by a dedicated hostile-character bats fixture and a well-formedness parse check |
| T-06-02 | Information Disclosure | `aggregated.json` contents rendered into SVG | accept | Contains only cost/token/pass-rate numbers and internal task/baseline ids already visible in committed `task.json`/`benchmarks/baselines/*.json` files — no secrets, no PII |
| T-06-03 | Denial of Service | A pathologically large `aggregated.json` (many cells) producing an oversized SVG | accept | Internal tooling only, never exposed to untrusted network input; the corpus is a pre-declared, bounded 6-task set (Phase 5), so cell count is bounded in practice |
| T-06-04 | Tampering (silent data fabrication) | A cell with `null` cost/token medians rendering as a `0`-valued bar, which a reader could misread as "measured, and it was free/zero" | mitigate | Explicit `class="bar-nodata"` / `no data` marker path, never a fabricated zero — proven by the Task 2 honesty bats test |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this plan — stdlib Python only, matching every other script in `benchmarks/scripts/`; the Package Legitimacy Gate does not apply |
</threat_model>
