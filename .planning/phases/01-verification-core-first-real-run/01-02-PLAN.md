## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| bench-run.py subprocess boundary <-> claude binary | Task prompt text and CLI flags cross a process boundary into an external CLI invocation |
| bench-run.py <-> stub binary (tests only) | A test double resolved purely via an env var; must never leak into a production/live run |
| JSONL row <-> committed repo file | Harness output becomes a git-committed artifact; must never carry secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-01-04 | Tampering | `subprocess.run` cmd construction in bench-run.py | mitigate | Argv list only, never `shell=True` or string-interpolated shell commands -- enforced by Task 1's acceptance criterion `grep -c 'shell=True' bench-run.py` == 0 |
| T-01-05 | Information Disclosure | ANTHROPIC_API_KEY / other env leaking into the committed JSONL row or bats logs | mitigate | The row schema is a fixed, explicit field list built from the parsed claude JSON response plus `task_id`/`wall_clock_ms`/`verify_passed` only; bench-run.py never dumps `os.environ` wholesale into the row or into any print statement |
| T-01-06 | Elevation of Privilege | `CAIRN_BENCH_CLAUDE_BIN` pointing at an unintended executable | accept | Dev-controlled env var, same trust level as `$PATH` itself; only ever set explicitly by bats tests in this repo or a deliberate operator override |
| T-01-07 | Tampering | claude subprocess escaping its intended workdir via `--add-dir` or absolute paths | mitigate | bench-run.py never passes `--add-dir`; `claude -p --bare`'s default scope is the invocation's cwd only |
| T-01-SC | Tampering | npm/pip/cargo installs | n/a | No new packages introduced this phase (Package Legitimacy Audit in 01-RESEARCH.md: N/A -- every tool used is stdlib or a pre-existing, already-vetted dependency); no install task exists in this plan. `tests/bench-verify.bats` and this plan's fixture/harness code use stdlib `unittest`, not `pytest` (per Plan 01's checker-revision decision) -- CI's lint/test steps require no new pip install |
