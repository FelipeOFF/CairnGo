## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| verify.sh <-> agent-writable workdir | verify.sh reads the outcome of code that will eventually be agent-produced, inside a disposable directory it is only handed a path to |
| bats test <-> hand-crafted fixture content | In this plan the fixture content is entirely repo-authored and static, not attacker- or agent-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-01-01 | Tampering | benchmarks/tasks/smoke-convert/verify.sh | mitigate | verify.sh lives outside every workdir (task-dir root, never inside fixture/); invoked with the workdir path as `$1`, never copied in -- proven by Task 2's test 3 asserting its absence from the checked workdir after a run |
| T-01-02 | Tampering / Elevation of Privilege | unittest execution against workdir code (celsius_to_fahrenheit implementation) | accept | This phase's fixture code is entirely repo-authored and static (no agent has run against it yet); running arbitrary code via unittest against future agent-produced code is an accepted, inherent risk of this benchmark's whole premise, always scoped to a disposable mktemp directory, never the real repo tree |
| T-01-03 | Information Disclosure | fixture/test content committed to the repo | accept | Fixture is intentionally trivial (temperature conversion), contains no secrets or PII |
</threat_model>
