<objective>
Make the lease visible where an agent already looks before touching a
phase: the status board's footer. One new line, own territory (D-05) —
deliberately NOT the phase table, which Plan 14 (running concurrently, in a
separate worktree) owns. Fix the one real bug this phase's mechanism
introduces on its own: the lease bookkeeping bd issue would otherwise show
up as a phantom card in the READY/DOING/BLOCKED lanes exactly like any
other tracked issue, since it is a real bd issue with a real status.

Purpose: LEASE-01/02 both require seeing a live conflict BEFORE entering a
phase — the footer is the surface an agent reads on every `/cairn:status`,
not only when it happens to run `/cairn:work`.

Output: `cairn-status.py` gains a lease-aware footer line (terminal,
--plain, HTML) and an additive `--json` key, and its lane fetch excludes
the lease issue from every rendered surface.
</objective>
