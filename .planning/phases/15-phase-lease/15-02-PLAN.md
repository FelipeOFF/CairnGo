<objective>
Wire the lease built in Plan 15-01 into the two points where phase work
actually starts and stops, through paths that survive a bare `/gsd:*` run —
not only a `/cairn:*`-initiated one.

`execute-wave-pre.md` and `verify-post.md` are capability FRAGMENTS,
injected into GSD's own executor/orchestrator via `capability.json`, and
this repo's own convention (`plan-post.md`, `execute-wave-post.md`,
`cairn-loop-gate.sh`'s own gate command in `capability.json`) is unanimous
that inside a fragment `${CLAUDE_PLUGIN_ROOT}` is the WRONG resolver — it
points at whatever plugin happens to be running the GSD workflow (gsd-core
during a bare `/gsd:*` call), not at cairn. Every fragment instead locates
the bundled `.gsd/capabilities/cairn` copy directly. `cairn/commands/work.md`
is different: it IS a cairn command, so `${CLAUDE_PLUGIN_ROOT}` there
correctly resolves to cairn's own plugin root (the same convention
`cairn-map.sh`'s own docstring documents as its resolution fallback #3,
"when running inside a cairn command") and stays unchanged.

Acquisition happens twice, deliberately, for two different reasons: once in
`work.md` before the per-plan claim loop (LEASE-01's "see this before you
enter"), and again in `execute-wave-pre.md` before every wave (the ongoing
heartbeat for a phase whose execution outlives a single session-start
renewal). Release happens once, in `verify-post.md`, unconditionally — pass
or fail, that is where a phase's cycle ends.

Purpose: a mechanism nobody can actually reach is not a feature. If
`verify-post.md`'s release call resolves to a path that does not exist
during a bare `/gsd:*` run, LEASE-04's "release happens once per phase, pass
or fail" is simply never delivered through its only documented path — and
no `.bats` test would catch it, because every existing test invokes
`cairn-lease.sh` directly with an explicit `--project-dir`, never through
real capability injection.

Output: a new vendored delegator shim
`cairn/capability/scripts/cairn-lease.sh` (mirroring `cairn-map.sh`, never
duplicating `cairn-lease.py`'s logic), plus `work.md`, `execute-wave-pre.md`
and `verify-post.md` each gaining one new step — the deterministic work
already lives in the shim and the real `cairn-lease.py` (Plan 15-01), these
files only decide when to call it, how to find it, and what to do with its
report.
</objective>
