# Codebase Structure

**Analysis Date:** 2026-07-25

CairnGo is a Claude Code **plugin marketplace repo**: the marketplace
manifest lives at the root, and it publishes one first-party plugin
(`cairn`) plus a pass-through dependency on the upstream `gsd` plugin. There
is no application build; "the codebase" is markdown (commands/skills/docs)
and small Python/bash scripts, tested with bats.

## Directory Purposes

**`.claude-plugin/`:**
- Purpose: the marketplace root manifest Claude Code reads to discover
  installable plugins
- Contains: `marketplace.json` only — `name`, `owner`, cross-marketplace
  dependency allowlist (`context-mode`), and the `plugins` array (each entry
  points at `./cairn` or an upstream GitHub repo for `gsd`)
- Key files: `.claude-plugin/marketplace.json`

**`cairn/`:**
- Purpose: the entire shippable plugin; everything a user gets from
  `/plugin install cairn@cairngo` lives under here
- Contains: its own `.claude-plugin/plugin.json`, plus commands, skills,
  capability, scripts, adapters, hooks, docs, templates
- Key files: `cairn/README.md` (feature tour), `cairn/.claude-plugin/plugin.json` (manifest)

**`cairn/commands/`:**
- Purpose: one prose file per `/cairn:*` slash command
- Contains: markdown with YAML frontmatter (`description`, optional
  `argument-hint`) and numbered-step instructions; most delegate to a script
  under `cairn/scripts/`
- Key files: `init.md` (setup), `migrate.md`, `doctor.md`, `ship.md`,
  `bd.md` (raw `bd` passthrough), `gsd.md` (raw GSD passthrough)

**`cairn/skills/`:**
- Purpose: standing conventions the agent follows in a session, activated by
  a gate condition documented at the top of each `SKILL.md` (e.g. "only when
  the repo has both `.planning/` and `.beads/`")
- Contains: one subdirectory per skill, each with exactly one `SKILL.md`
- Key files: `cairn/skills/cairn/SKILL.md` (the core model — labels,
  metadata stamp, precedence rules), `cairn-sync/SKILL.md`,
  `cairn-context/SKILL.md`

**`cairn/capability/`:**
- Purpose: the sanctioned GSD extension point — code-level enforcement
  installed into a *user's project* (`.gsd/capabilities/cairn/`), not run
  from inside this repo
- Contains: `capability.json` (contribution/gate manifest), `fragments/*.md`
  (prose injected into GSD's planner/executor/orchestrator at named loop
  points), `scripts/cairn-loop-gate.{sh,py}` and `scripts/cairn-map.sh` (a
  self-contained bundled copy so the staged capability doesn't depend on the
  plugin's own `scripts/` dir being reachable)
- Key files: `cairn/capability/capability.json`

**`cairn/scripts/`:**
- Purpose: every deterministic, testable behavior in the plugin
- Contains: Python implementations (`.py`, stdlib only) paired 1:1 with thin
  bash exec-wrappers (`.sh`) of the same base name
- Key files: `cairn-init.sh/.py`* (*init.sh has no .py pair — it's pure
  bash), `cairn-gate.py` (ship gate), `cairn-map.py` (regenerate
  `NN-BEADS-MAP.md`), `cairn-migrate.py` (~1750 lines — the largest file in
  the repo, drives the A/B/C/W/D migration engine), `cairn-doctor.py`
  (health checks), `cairn-relabel.py` (label-pair backfill), `gbsync.py`
  (sync dispatcher)

**`cairn/adapters/`:**
- Purpose: one executable per external issue tracker, isolated from the
  dispatcher by a stdin/stdout JSON contract
- Contains: `_contract.md` (the contract itself — push/pull payload shapes,
  status normalization table, secrets handling), one script per backend
- Key files: `github.py`, `gitlab.py`, `jira.py`, `asana.py`,
  `azure-boards.py`

**`cairn/hooks/`:**
- Purpose: Claude Code lifecycle automation that runs without any explicit
  command
- Contains: `hooks.json` (event -> command registration for `SessionStart`,
  `PostToolUse`, `Stop`), the three shell scripts it registers
- Key files: `post-bd-write.sh` (the busiest one — parses the hook payload,
  fires mirror push + map refresh)

**`cairn/docs/`:**
- Purpose: long-form guides too big for a `SKILL.md` or command file
- Contains: `architecture.md` (read this before touching any integration
  surface — the canonical design doc this ARCHITECTURE.md draws from),
  `migration.md`, `sync.md`, `context.md`

**`cairn/templates/`:**
- Purpose: example config files shown to users, never executed
- Contains: `context.json.example`, `sync.json.example`
- Generated: No. Committed: Yes.

**`tests/`:**
- Purpose: the bats suite — the only place cairn behavior is verified
  end-to-end
- Contains: `helpers.bash` (fixture factories: `require_bd`,
  `make_tmp_repo`, `make_gsd_fixture`, `make_bd_fixture`,
  `extract_frontmatter`/`assert_frontmatter_key`/`assert_json_eq`), one
  `<script-name>.bats` per script under test, plus `smoke.bats` and
  `capability.bats`
- Key files: `tests/README.md` (documents the seam: assert on script CLI
  output/exit codes/`bd list --json`, never on internals)

**`.agents/skills/beads/`:**
- Purpose: a copy of beads' own cross-runtime skill definition (not
  authored by cairn) so non-Claude-Code agents (e.g. via `agents.yaml`) get
  the same `bd` conventions
- Generated: No (vendored/synced from the `beads` project). Committed: Yes.

**`.codex/`:**
- Purpose: wires this repo's *own development loop* into the Codex CLI
  (an agent runtime other than Claude Code), delegating every lifecycle
  event to `bd codex-hook <event>`
- Contains: `config.toml` (`[features] hooks = true`), `hooks.json`
  (`PostCompact`, `PreCompact`, `SessionStart`, `UserPromptSubmit`)
- Note: this is infrastructure for developing *this* repo with Codex, not
  part of the shippable `cairn` plugin itself.

**`.beads/`, `.planning/`:**
- Purpose: this repo dogfoods its own product — `bd` tracks CairnGo's own
  work items, GSD tracks CairnGo's own roadmap/phases
- Generated: Yes (state files). Committed: `.planning/*.md` yes;
  `.beads/` internals are gitignored (`.dolt/`, `*.db`,
  `.beads-credential-key`, `.beads/proxieddb/` — see `.gitignore`)

**`.pr-autopilot/`:**
- Purpose: working state for an external PR-review-automation tool (per-PR
  number subdirectories with `state.json`, iteration review reports)
- Generated: Yes. Committed: currently present in the tree but not part of
  the plugin's own code paths — treat as tool scratch space, not source.

## Key File Locations

**Entry Points:**
- `.claude-plugin/marketplace.json`: marketplace discovery root
- `cairn/.claude-plugin/plugin.json`: plugin manifest (name, version,
  dependencies `gsd` + `context-mode`, keywords)
- `cairn/commands/*.md`: every `/cairn:*` slash command
- `cairn/capability/capability.json`: every GSD loop-point contribution and
  the `ship:pre` gate

**Configuration:**
- `cairn/capability/capability.json` `config` block: `cairn.enabled` (master
  toggle), `cairn.sync_push` (mirror-on-write toggle)
- `.cairn/sync.json` (in a *consuming* project, not this repo):
  external-tracker backend config — the only committed `.cairn/*` file, per
  `cairn-init.sh`'s gitignore wiring
- `cairn/templates/*.example`: shape reference for `sync.json`/`context.json`

**Core Logic:**
- `cairn/scripts/cairn-gate.py`: the ship gate (also mirrored at
  `cairn/capability/scripts/cairn-loop-gate.py` for the bundled capability)
- `cairn/scripts/cairn-map.py`: generates `NN-BEADS-MAP.md`
- `cairn/scripts/cairn-migrate.py`: the migration engine (detect/plan/confirm/apply)
- `cairn/scripts/cairn-doctor.py`: drift/health checks
- `cairn/scripts/gbsync.py` + `cairn/adapters/*.py`: sync dispatch + backends

**Testing:**
- `tests/*.bats`: one suite per script, named after the script under test
  (`cairn-gate.bats`, `cairn-map.bats`, `cairn-migrate.bats`,
  `cairn-doctor.bats`, `cairn-relabel.bats`, `gbsync.bats`, `hooks.bats`,
  `capability.bats`, `cairn-init.bats`, `smoke.bats`)
- `tests/helpers.bash`: shared fixture/assertion helpers

## Naming Conventions

**Files:**
- Scripts: `cairn-<verb>.py` (implementation) + `cairn-<verb>.sh` (exec
  wrapper), e.g. `cairn-gate.py`/`cairn-gate.sh`. The non-cairn-prefixed
  `gbsync.py`/`gbsync.sh` is the one exception (predates the `cairn-`
  convention / named for its own concept — "GitHub-beads sync").
- Commands: `<verb>.md` under `cairn/commands/`, filename == the text after
  `/cairn:` (e.g. `cairn/commands/ship.md` -> `/cairn:ship`)
- Skills: `<skill-name>/SKILL.md`, always uppercase `SKILL.md` inside a
  lowercase-hyphenated directory (`cairn-sync/SKILL.md`)
- Tests: `<script-base-name>.bats` matching the script it exercises 1:1
- Docs: lowercase-hyphenated under `cairn/docs/` (`architecture.md`,
  `migration.md`); repo-root docs are UPPERCASE (`README.md`,
  `CONTRIBUTING.md`, `CHANGELOG.md`)

**Directories:**
- Plugin-internal dirs are singular-purpose nouns, lowercase, no
  abbreviation ambiguity: `commands/`, `skills/`, `scripts/`, `adapters/`,
  `hooks/`, `docs/`, `templates/`, `capability/`
- Generated/local state directories are dot-prefixed and scoped to the
  owning tool: `.cairn/` (cairn's own local state), `.beads/` (beads),
  `.planning/` (GSD), `.gsd/capabilities/cairn/` (where the capability
  bundle gets staged in a *consuming* project)

## Where to Add New Code

**New `/cairn:*` command:**
- Prose: `cairn/commands/<verb>.md` (frontmatter `description`, optional
  `argument-hint`)
- If it needs deterministic behavior: implement that behavior as a new
  script in `cairn/scripts/` first (see CONTRIBUTING.md — "scripts over
  prose"), then have the command shell out to it
- Update `cairn/commands/help.md` if it should show up in the unified
  command map

**New deterministic script:**
- Implementation: `cairn/scripts/<name>.py` (stdlib only — no third-party
  imports; must run anywhere Claude Code runs)
- Wrapper: `cairn/scripts/<name>.sh` — copy the 7-line pattern from
  `cairn-map.sh`/`cairn-gate.sh` (`exec python3 "$HERE/<name>.py" "$@"`)
- Tests: `tests/<name>.bats` is mandatory per CONTRIBUTING.md ("Every new
  script ships with a `.bats` file")
- If the script needs to run *inside* a GSD loop point rather than be
  invoked by a command: add a fragment under
  `cairn/capability/fragments/*.md` and register it as a `contribution` (or
  `gates` entry) in `cairn/capability/capability.json`, and mirror the
  bundled-script copy into `cairn/capability/scripts/` if it must be
  self-contained once staged

**New sync adapter (external tracker):**
- Implementation: `cairn/adapters/<tool>.py`, following the contract in
  `cairn/adapters/_contract.md` exactly (stdin JSON action envelope, stdout
  bare-string/JSON-array result, exit 0/nonzero)
- No dispatcher changes needed beyond registering the backend name where
  `gbsync.py` resolves adapters (adapters are auto-detected by presence)

**New convention (no code needed):**
- Add to the relevant `cairn/skills/*/SKILL.md`, but only for genuinely
  non-deterministic guidance — if it can be checked by a script, it belongs
  in `cairn/scripts/` instead per the anti-pattern documented in
  ARCHITECTURE.md ("Landing new deterministic behavior as prose only")

**Utilities:**
- Shared test fixtures/assertions: `tests/helpers.bash`
- There is no shared runtime utility module (no `lib/` or `common.py`) —
  each script is self-contained by design; duplication of small helpers
  (e.g. `die()`) across scripts is the accepted tradeoff for
  dependency-free, independently-testable CLIs

## Special Directories

**`cairn/adapters/__pycache__/`, `cairn/scripts/__pycache__/`, `cairn/capability/scripts/__pycache__/`:**
- Purpose: Python bytecode cache from local script runs
- Generated: Yes. Committed: No (`__pycache__/`, `*.pyc` in `.gitignore`)

**`.beads/`:**
- Purpose: this repo's own beads database (dogfooding)
- Generated: Yes. Committed: partially — Dolt/db internals gitignored,
  directory itself may be tracked for structure

**`.planning/`:**
- Purpose: this repo's own GSD planning tree (dogfooding); `.planning/codebase/`
  specifically is where `/gsd:map-codebase` (this very run) writes its output
- Generated: `.planning/codebase/*.md` yes (by this command); other
  `.planning/*.md` files (ROADMAP, phases) are agent-authored via GSD
  commands, not auto-generated
- Committed: Yes

**`.pr-autopilot/`:**
- Purpose: scratch/state for an external PR-automation tool, keyed by PR
  number
- Generated: Yes. Committed: currently present but not source code — do not
  treat as part of the plugin surface
